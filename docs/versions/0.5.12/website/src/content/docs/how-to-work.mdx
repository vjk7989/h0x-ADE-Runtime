---
title: How to work with HyperOx
description: Run HyperOx locally, inside SSH, or through remote attach.
---

Run HyperOx where the work lives. Attach from wherever you are.

HyperOx is a background session server plus one or more terminal clients. Panes keep running in the server. Clients attach, detach, and render the session.

## Local work

Start HyperOx from the project directory:

```bash
h0x
```

HyperOx starts or attaches to your local background session automatically. You do not manage sockets. Run shells, servers, tests, and agents normally inside panes.

Detach the client with `ctrl+b q`. Your panes keep running.

Reattach later:

```bash
h0x
```

If you want to end the session and stop its panes, stop the server:

```bash
h0x server stop
```

## Remote work through normal SSH

SSH to the machine that has the code and credentials, then run HyperOx there:

```bash
ssh you@server
h0x
```

This works like a terminal multiplexer. Your shell is remote. The HyperOx server is remote. The agents and panes run on the remote machine. Detach with `ctrl+b q`, disconnect, then SSH back and run `h0x` again.

Use this path when you already live inside an SSH shell, when you are on a phone or tablet SSH client, or when you want the simplest possible setup.

## Work from your phone

You do not need a HyperOx mobile app or a web dashboard. Install any SSH client on your phone, connect to the machine where your agents run, and start HyperOx there:

```bash
ssh you@server
h0x
```

The same persistent HyperOx session opens in your phone terminal. The TUI adapts to narrow screens, so you can inspect agents, switch workspaces, and check panes without leaving SSH.

On iPhone, apps like [moshi](https://getmoshi.app/) work well.

## Remote work from your local terminal

Attach through SSH without opening a shell first:

```bash
h0x --remote workbox
h0x --remote ssh://you@server:2222
```

Your local HyperOx acts as a thin client. It connects over SSH, starts or attaches to the remote HyperOx server, and streams the UI back to your local terminal.

Use this path when you want one local command that opens the remote HyperOx session directly.

For repeat targets, put the host in your SSH config:

```text
Host workbox
  HostName server.example.com
  User you
  Port 2222
```

Then attach with:

```bash
h0x --remote workbox
```

## Which path to use

Use `h0x` for local work. Use `ssh you@server` then `h0x` when you want HyperOx to behave like tmux on that remote shell. Use `h0x --remote <host>` when you want your local terminal to attach directly to the remote HyperOx session over SSH.

For remote bootstrap details, named remote sessions, custom binaries, direct terminal attach, and `--no-session`, see [Persistence and remote access](/docs/persistence-remote/).
