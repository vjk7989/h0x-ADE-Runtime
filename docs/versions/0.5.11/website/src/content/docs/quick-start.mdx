---
title: Quick start
description: Create your first HyperOx workspace and run agents in persistent terminal panes.
---

Start HyperOx from any project directory:

```bash
h0x
```

HyperOx launches or attaches to your default background session. If you detach, agents keep running.

## Create a workspace

Press `n` to create a workspace. A workspace is a project-level container for tabs, panes, and agents.

Give each active project its own workspace. This keeps agent state readable in the sidebar.

## Run an agent

Start your agent in the root pane.

```bash
pi
```

HyperOx detects supported agents automatically. The sidebar shows whether each agent is `working`, `blocked`, `done`, or `idle`.

## Navigate

Press `ctrl+b` to enter navigate mode.

Common actions:

| Action | Key |
| --- | --- |
| Split right | `v` |
| Split down | `-` |
| New tab | `c` |
| New workspace | `n` |
| Detach client | `q` |

After detaching, run `h0x` again to reattach to the same session.

## Use the mouse

HyperOx is mouse-native. You can click panes, tabs, workspaces, and agents; drag borders; select text; and use right-click menus.

## Manage named sessions

Named sessions are separate HyperOx server namespaces. Use them when you want fully separate runtime state.

```bash
h0x session list
h0x session attach work
h0x session attach side-project
h0x session stop work
h0x session delete side-project
```

Workspaces are usually enough. Use named sessions when you need isolation between sets of panes, sockets, and persistent state.

## Attach from another machine

Start HyperOx on a server, detach, and come back over SSH later.

```bash
ssh you@server
h0x
```

You can also attach through SSH from your local terminal:

```bash
h0x --remote workbox
h0x --remote ssh://you@server:2222
```

For repeat targets, put the host in your SSH config.
