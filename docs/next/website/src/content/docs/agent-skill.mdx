HyperOx ships a reusable agent skill file at [`skills/h0x/SKILL.md`](https://github.com/vjk7989/h0x-ADE-Runtime/blob/main/skills/h0x/SKILL.md).

Install that file into any coding agent that supports reusable skills or custom instructions. The skill teaches the agent how to control HyperOx from inside a HyperOx pane.

## What the skill does

The skill tells an agent to use the `h0x` CLI when `H0X_ENV=1` is set. That means the agent is running inside a HyperOx-managed pane and can safely talk to the local HyperOx socket.

With the skill installed, an agent can:

- inspect workspaces, tabs, panes, and neighboring agents
- split panes and run commands without stealing focus
- read pane output and recent logs
- wait for servers, tests, or another agent to finish
- start helper agents in sibling panes

The skill is a Markdown instruction file for agents. If HyperOx is already installed, run `h0x --skill` to print the release-matched copy bundled with that binary.

## Install it

Install the skill with `npx skills`:

```bash
npx skills add vjk7989/h0x-ADE-Runtime --skill h0x -g
```

If you installed the skill while it lived at the repository root, rerun this add command once instead of using `skills update`. The add command replaces the oversized copy and records the new location.

The `-g` flag installs it globally for supported agents. Omit `-g` to install it into the current project.

Use the repository copy as the manual fallback and source of truth:

```text
https://github.com/vjk7989/h0x-ADE-Runtime/blob/main/skills/h0x/SKILL.md
```

For agents with a skill system, install that file as a skill named `h0x`. For agents without a skill system, paste the file into the agent's project or user instructions.

After installation, start the agent inside HyperOx:

```bash
h0x
claude
```

Or use any other coding agent in a HyperOx pane so `H0X_ENV=1` is available to the agent process.

## Safety rule

The skill starts with one guardrail: if `H0X_ENV=1` is not set, the agent should stop and say it is not running inside a HyperOx-managed pane.

This prevents an agent outside HyperOx from trying to control a session it does not own.
